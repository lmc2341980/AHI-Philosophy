# AHI-Philosophy — Dynamic Working Protocol v1.0

Status: APPROVED WORKING ARTIFACT
Version: v1.0.0

## 1. Working Sequence

For each significant task:

1. Load authoritative sources and relevant indexes.
2. Identify the problem or objective.
3. Determine current priority.
4. Measure data size and weight.
5. Measure query volume and complexity.
6. Check hardware and software resources.
7. Select suitable indexing or partitioning.
8. Execute the work.
9. Measure the result.
10. Evaluate suitability in the target environment.
11. Record success, failure, limitation, or uncertainty.
12. Promote knowledge only to the level justified by validation.
13. Preserve provenance and evolution.
14. Update the applicable WORKING-INDEX / Working Handoff.
15. Continue the next priority task.

## 2. Source-First

Use:

Source
↓
Evidence
↓
Validation
↓
Conclusion

Never convert:

Inference → Fact
Proposal → Fact
Opinion → Fact
AI Output → Truth
Memory → Truth

If evidence is insufficient, use:

UNKNOWN
UNDEFINED
UNVERIFIED
PROPOSAL

## 3. Dynamic Indexing

Do not assume a fixed number of index levels.

Select indexing depth from:

Hardware
+
Data Weight
+
Query Load
+
Query Complexity
+
Concurrent Users
+
Response Time
+
User Feedback
+
Resource Availability

Current working model:

Level 1 — Philosophy / Artifact
Level 2 — AHI-V
Level 3 — AHI-SuBiet

The model may evolve when measurement and practice demonstrate a better structure.

## 4. Dynamic Priority

Initial order:

Urgent + Important
→ Urgent
→ Important
→ Later / lower priority

Where appropriate, use weighted:

- urgency;
- importance;
- impact;
- dependency;
- cost;
- risk;
- deadline;
- workload;
- user need.

Priority may be recalculated as conditions change.

## 5. Idle-Time Processing

When sufficiently idle, evaluate:

- pending work;
- priority;
- indexing depth;
- resource consumption;
- query performance;
- previous experiments;
- validation status.

Use idle resources for safe optimization and re-indexing without harming active high-priority work.

## 6. Validation Levels

Keep distinct states:

PROPOSAL
→ EXPERIMENTAL
→ MEASURED
→ PRACTICALLY USED
→ VALIDATED
→ EVOLVING KNOWLEDGE

Do not promote a result merely because it was generated or executed successfully.

## 7. Output Quality Gate

Before presenting an artifact or recommendation, check:

- Can the target user actually use it?
- Does it work in the target environment?
- Is the output size appropriate?
- Are paths and names correct?
- Is the format appropriate?
- Is provenance preserved?
- Has the result been tested where practical?

If not verified, state the limitation.

## 8. Continuity

At the end of meaningful work, update the applicable:

WORKING-INDEX
Working Handoff
Artifact status
Version
History

Do not silently delete historical information.
