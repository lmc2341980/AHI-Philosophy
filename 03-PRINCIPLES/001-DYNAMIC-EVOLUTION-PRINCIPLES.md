# Le Minh Philosophy — Dynamic Evolution Principles v1.0

Status: APPROVED WORKING ARTIFACT
Version: v1.0.0

## 1. Purpose

These principles operationalize the parallel evolution of Triết học Lê Minh and the AHI Ecosystem through practice, measurement, validation, and preserved provenance.

This is a working artifact and does not replace the Constitution.

## 2. Dynamic Indexing Principle

Indexing is adaptive, not permanently fixed.

Index depth and partitioning are determined from:

- hardware capacity;
- data size and weight;
- data structure;
- query volume;
- query complexity;
- concurrent users;
- response time;
- user feedback;
- available software and system resources.

The current working model is:

1. Philosophy / Artifact — small and detailed working units.
2. AHI-V — constitutional constraints and high-priority validation.
3. AHI-SuBiet — broader and larger knowledge structures.

These are an initial working model, not a permanent limit.

The system may split, merge, cache, index, or reorganize information when evidence demonstrates that doing so improves practical performance.

## 3. Dynamic Priority Principle

Initial priority:

1. Urgent + Important
2. Urgent
3. Important
4. Normal / Not urgent / Not important — processed later according to capacity and dependencies.

Future versions may use weighted:

- urgency;
- importance;
- impact;
- dependency;
- resource cost;
- query load;
- deadline;
- risk;
- user need.

Priority is therefore a changing operational value, not a permanent label.

## 4. Idle-Time Evolution

When system load is sufficiently low, available resources may be used to:

- evaluate the work queue;
- recalculate priorities;
- measure data and query characteristics;
- optimize indexing and partitioning;
- validate previous changes;
- benchmark alternatives;
- record successful and unsuccessful experiments;
- preserve provenance and evolution history.

Idle-time optimization must not degrade higher-priority active work.

## 5. Measurement Before Elevation

The required progression is:

Proposal
→ Experiment
→ Measurement
→ Evaluation
→ Practical Use
→ Validation
→ Evolving Knowledge

An inference is not a fact.

A proposal is not knowledge.

Successful execution is not automatically validated knowledge.

When a person successfully uses an output in practice at least once, that result may be recorded as a practical instance of "Sự Biết", while retaining its evidence and validation status for further testing.

## 6. Continuous Evolution

Observation
→ Measurement
→ Hypothesis
→ Experiment
→ Evaluation
→ Validation
→ Knowledge
→ Practice
→ Feedback
→ Evolution
→ Observation

Previous versions must not be silently erased.

Evolution must preserve:

- source;
- version;
- history;
- feedback;
- validation status;
- provenance.
